## 视觉规范
主色 #0F2742 深海军蓝，背景 #F9F6EE 象牙白，装饰 #C6A774 学术金，辅助 #5A6B62 墨绿灰。深色正文与深金色文本保证浅底可读性；不使用浅金色正文。宋体类标题、系统无衬线正文，无外网字体依赖。原创简洁书本星形标识和抽象学院建筑线稿，不影射特定高校或使用其官方标识。

## 实现
- 备考端：桌面固定深蓝侧栏、搜索与账号区、既有全部入口；手机保留原导航抽屉，增加首页/学习/笔记/研究/档案快捷导航。
- 今日学习：左侧真实学习记录/复习/近期档案，右侧 AI 与研究快捷卡片，底部原有学习入口。只有实际 API 返回的计数，没有假完成率、假时长、虚构书目或文献数量。AI 卡片仅导航至现有研究助手，不假装聊天或直接发送材料。
- 文学研究：同品牌标识、深蓝页首、金色选中标签、象牙白卡片、议题双列、引用/对照配色、笔记编辑区域与手机快捷导航。保留原 Radix Tabs、弹窗、材料确认、举报/屏蔽与所有 API。
- 概念稿中的三栏笔记管理、右侧实时段落批注、独立聊天、项目文件夹、学习计划、全文文献检索、深色模式不是本次实现；不制造假入口。样式升级首版，需真实浏览器视觉验收。

## 审核及合并顺序
1. 视觉 PR 的 base 是 feature/knowledge-community-v2，Files changed 应仅包含视觉变更。
2. 先完成 PR #3 审核与实际验收。同学获授权可自行合并，无需用户第二次审批；助手不自动合并。
3. 合并 PR #3 后保留基线分支，先将视觉分支同步到新的 main（若 squash/rebase 合并则谨慎只移植视觉提交，避免把旧功能重复合入）。处理冲突后将视觉 PR base 改为 main，确认 diff 仅包含美工变更，再执行完整 CI。
4. 原 CI workflow 的 pull_request 只针对 main，堆叠 PR 不保证自动触发。可由有权限维护者在独立 checkout 使用 pnpm install --frozen-lockfile、node scripts/prepare-ocr.mjs、pnpm run build、pnpm exec tsc --noEmit、node scripts/verify-ci.mjs 核验；也可在 GitHub Actions 对视觉分支手动 Run workflow。
