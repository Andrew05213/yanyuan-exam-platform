# 主观题 AI 批改

作文、翻译和口试文字作答通过服务端调用后台配置的默认 Provider 和模型。支持 OpenAI 兼容的 Chat Completions 接口，包括 DeepSeek；其他协议暂不能用于批改。管理员须保存密钥、模型、启用 Provider 并设为默认。价格可留空，但缺少必要价格时费用显示未知。

客观题继续在本地对照参考答案判分，不调用模型、不产生 AI 用量。人工填分入口保持移除，历史分数和折叠的批改 JSON 导入仍保留。未完成批改的主观题不视为零分，也不显示完整整卷总分。

## 页面流程

- 点击「AI 批改」先保存当前作答，再提交档案编号、题号、版本及请求编号。题目和原稿由服务端按登录身份读取，不接受客户端指定计费用户或模型。
- 作文原稿必须核对确认。返回结果经过六维评分、逐句原文覆盖与总分校验；首次批改及原稿保留，复评追加保存。
- 混合卷作文、翻译使用百分制评语，按本题分值折算。评分绑定完整题目、材料和实际作答；修改后旧 AI 分数失效。
- 口试仅评价用户填写的文字转写，不发送录音，也不评价发音、语速或流利度；自动语音转写尚未实现。
- 批改期间可以编辑。返回时按原稿指纹及档案版本检查，不能覆盖较新的修改；未能应用的结果保留在本人批改任务中，成绩保持原状。

## 接口和故障处理

`GET /api/ai-grading` 返回默认配置是否就绪；未配置时按钮禁用并提示管理员设置。`POST /api/ai-grading` 接受 `{recordId, questionId?, expectedRevision, requestId}`。登录、同源、档案所有权和版本均须通过检查。客观题不能通过此接口发起模型调用。

`GET /api/ai-grading?jobId=…` 仅向任务所有者返回状态与结果。同一用户、同一请求编号重发只查询原任务，不重复请求上游；每人同时只允许一个进行中的任务。上游请求不自动重试，超时或断线不伪造分数或用量；用户需核对状态再决定是否重新批改。5 分钟仍未完成的任务标为未知。

模型输出有大小和结构限制；总分不符、缺少逐句分析、截断和错误响应均不计入成绩。上游返回了真实用量时，失败的批改仍然记录用量。网络中断后是否扣费无法确认时保留未知，不能当作免费。

## 配置、数据与验证

密钥只在服务端解密。请求只允许官方 API 主机或服务端 `AI_MODEL_HOSTS` 显式允许的可信主机，禁止跟随重定向，设有超时和响应体上限。不要把内网服务或不受信任的地址加入允许列表。

在既有迁移后追加应用 `drizzle/0005_modern_valeria_richards.sql`，建立所有者隔离的批改任务及并发约束。不要重建原有档案、Provider 或用量表。费用规则和价格快照见 [管理后台](admin.md)。

构建后运行 `node scripts/verify_ai_contracts.mjs` 和 `node scripts/verify_ai_grading.mjs`。后者使用隔离 Worker、数据库和模拟上游，覆盖三类主观题、真实用量字段、费用、重复请求、客观题拒绝、身份隔离、非法评分和并发修改，不产生真实模型费用。
