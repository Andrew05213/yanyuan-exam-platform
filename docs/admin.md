# 管理后台

入口：`/admin`。首页登录区只对管理员显示入口，后台的每个数据接口独立校验管理员身份。普通用户不能读取 Provider、用户用量或费用，也不能写入配置。

## 服务端配置

部署环境需要设置以下变量；本地使用被 Git 忽略的 `.dev.vars`：

- `ADMIN_EMAILS`：管理员邮箱，逗号或换行分隔，忽略大小写。身份来自托管平台注入的认证信息，不接受浏览器提交的角色。
- `ADMIN_USER_IDS`：可选的可信用户编号白名单。本地开发账号可设为 `local_seedy`，不要把本地账号加入生产环境。
- `AI_CREDENTIALS_ENCRYPTION_KEY`：32 字节随机值的 Base64 编码，存入部署平台的服务端 Secret。不要放入前端、代码仓库或数据库。

未配置白名单时，所有人都无法访问后台。未配置有效加密主密钥时，可以编辑普通配置，但拒绝写入 API Key。更换主密钥会使已保存的 API Key 无法解密；必须保留原主密钥或重新录入所有 Provider 的 Key，不要随意重新生成。

使用 D1 的新迁移 `drizzle/0003_wandering_salo.sql` 建表。按项目原有迁移流程应用未执行的迁移，不要重复执行已有迁移或重建业务数据。

## Provider 与密钥

新建 Provider 默认提供 DeepSeek 预设（OpenAI 兼容接口、官方地址、`deepseek-flash`），也可以切换为自定义。预设不会覆盖已保存的默认 Provider，也不自动设置价格。

保存配置和密钥后，点击“从上游获取模型”可读取 OpenAI 兼容 `/models` 列表，选择后需保存才生效。页面展示上游提供的名称、上下文窗口、输出上限及部分能力；未提供的信息保持未知，价格不会自动推算。密钥仅在服务端解密并发送到已保存的上游，响应、错误及审计均不包含密钥。

模型获取默认允许 DeepSeek、OpenAI、Mistral、Groq、OpenRouter 和 SiliconFlow 的官方 API 主机。其他受信任主机需由部署者在服务端 `AI_MODEL_HOSTS` 中显式配置（逗号分隔的主机名）。请求禁止重定向，设有超时与响应大小上限；模型获取不调用批改、不生成 Token 消耗记录。

支持记录多个 Provider 的名称、协议、公开 HTTPS 接口地址、模型、启用状态、默认项和模型单价。默认项全局唯一，停用默认项会取消其默认状态。两位管理员同时修改同一配置时，后提交的旧版本会返回冲突，刷新后再修改。

API Key 只能新增、更换或清除：留空保留现有值，清除需要勾选清除选项。接口仅返回“是否已设置”和更新时间，不返回原文、密文、前后缀或摘要。数据库保存带随机 IV、绑定 Provider 编号的 AES-GCM 密文。保存失败也会清空页面中刚输入的密钥。审计记录只保存操作者、动作、Provider 编号和时间，不保存请求正文或密钥。

主观题批改使用已启用的默认 Provider、已保存的模型和密钥，目前支持 OpenAI 兼容协议（含 DeepSeek）。配置就绪后，用户点击「AI 批改」才调用模型；保存配置或获取模型列表本身不会产生批改费用。其他协议可保存配置，暂不能用于批改；价格由管理员填写，不自动定价。追加应用 `drizzle/0005_modern_valeria_richards.sql` 后启用批改任务存储，详见 [批改流程](ai-grading.md)。

## 用量与费用

后台支持按北京时间日期、用户、Provider 和请求状态筛选，提供按用户汇总、单个用户调用明细及分页。登录后会记录用户编号和平台提供的邮箱、名称；历史记录若没有邮箱，仅显示用户编号。没有调用的用户显示“暂无调用”。

当前批改服务在服务端执行以下流程：

1. 使用可信认证身份确定用户，不接受前端传来的计费用户。
2. 用 `providerForExecution()` 读取启用的配置，并在请求前保留模型、币种、版本和价格快照。密钥只能用于服务端请求，不能进入响应、日志、错误信息、用量或审计记录。
3. 校验目标 HTTPS 地址和可信主机允许列表，禁止跟随重定向。额外主机只能由部署者通过 `AI_MODEL_HOSTS` 配置；不要允许内网或不受信任的主机。
4. 发送前用 `recordAIUsage()` 写入未知用量，响应后由 `finalizeAIUsage()` 写入上游真实报告的输入、缓存输入和输出 Token。输入 Token 已包含缓存部分；无法确定的字段保留 `null`。失败请求同样记录；断线未收到用量时保留未知。
5. 同一次上游请求使用稳定的 `requestId`；同 Provider 与 requestId 重复提交不会重复计费，内容不一致会拒绝。真正重试产生新的上游请求应使用新的 requestId。

没有向浏览器开放用量写入接口。客观题本地判分不产生 AI 用量。计费用户取自可信登录身份，不补造历史调用。

价格单位为对应币种每百万 Token，最多六位小数。输入、缓存输入、输出分别计价：`(输入−缓存)×输入价 + 缓存×缓存价 + 输出×输出价`，除以一百万，单次估算四舍五入到货币的百万分之一。总 Token 为输入加输出，缓存不重复累加。

空价格为未知，数字 0 才表示免费。缺失用量或必要价格时，费用显示未知；汇总同时给出已知部分，不把未知当零。不同币种分开汇总，修改价格不改变历史快照或历史费用。这里是配置单价下的估算，实际账单以 Provider 为准。

## 验证

新增“质量反馈”页签，仅展示用户主动提交的整卷评价、题目快照和意见。管理员可以标记待处理、已处理或暂不采纳，并填写处理说明；旧页面不能覆盖另一位管理员的新回复。列表读取与处理尝试写入 `admin_access_log`，需追加执行 `drizzle/0004_pink_pyro.sql`。

管理员身份不提供私人档案查阅权限：其他用户的作文、作答、原稿图片和录音继续按所有者隔离。压缩包中的私人档案管理接口未合入。

构建后运行 `node scripts/verify_admin.mjs` 检查隔离 Worker 中的权限、密钥写入、版本冲突、用量记账与统计；运行 `node --experimental-strip-types scripts/verify_admin_contracts.mjs` 检查加密及金额计算。测试仅使用虚拟身份和虚拟密钥，不调用模型或生产服务。
