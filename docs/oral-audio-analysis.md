# 原音口语分析

这是现有口试录音功能的增量：让支持音频输入的模型直接分析原音，提供转写、发音、语调和流利度建议，并显示 WAV 时长及估计停顿。结果是独立训练参考，不计入考试总分；文字 AI 批改和客观题本地判分沿用原流程。

## 配置和费用

在管理后台的「Provider 与密钥」保存一个已启用、已设置密钥的 OpenAI 兼容 Provider，然后在「原音分析」独立选择 Provider、填写原音模型并保存。可从上游获取模型列表，也可手动填写；模型必须实际支持 Chat Completions 的 `input_audio` 输入，列表存在不代表支持音频。

原音模型单独存储，不修改 Provider 自身的模型、密钥或文字默认项，因此当前 DeepSeek 文字批改不会改变。选择「不启用原音分析」并保存可停用，录音保存、播放和文字批改继续可用。Provider 被停用、清除密钥或协议不兼容时不会自动改用文字 Provider。

文字协议选择 Responses 的 OpenAI Provider 也可复用于原音分析，沿用同一份加密 Key、单独选择音频模型。原音请求使用 `/chat/completions` 的 `input_audio`，不把 WAV 直接发送给 `/responses`。同一 Key 能否调用某个模型由上游账号权限决定；模型列表中出现并不保证支持当前任务。

既有数据库追加应用 `drizzle/0006_oral_audio_settings.sql`，只新增任务配置表，不重建原有数据。尚未在后台保存时，兼容旧的 `ORAL_AUDIO_PROVIDER_ID` 及该 Provider 的模型；后台首次保存（包括停用）后以数据库配置为准，无需重启服务。配置采用版本校验，避免多位管理员相互覆盖；变更原音模型后，用户必须重新同意发送录音。

管理员身份仍只由服务端 `ADMIN_EMAILS` 或 `ADMIN_USER_IDS` 确定，没有写在源码中的默认管理员名单。原有十校预设和题库不作替换。

音频调用使用现有所有者隔离的任务表与内部用量账本，记录上游实际返回的 Token。音频与文字价格口径可能不同，目前音频价格和费用保留未知，不套用文字单价，也不把未知当成免费。准确的音频费用计算需要后续增加音频单价配置。

## 录音、同意和历史结果

分析接收 1—300 秒、10 MB 以内的 16 位 PCM WAV。浏览器提供本机转换选项；无法转换的格式仍可保存播放，不能据此宣称可分析。静音和停顿采用能量阈值估计，不代表精确的人声检测。

发送前须勾选当前录音的同意选项并点击分析。更换用户、录音或题目会立即清除旧反馈与同意；仅修改文字要点不影响同一原音的历史反馈。服务商配置变化也需要重新确认，异步保存期间不会把旧同意用于新服务商。迟到的旧请求不覆盖新的录音页面。

结果和任务按登录用户隔离。重复查询同一请求不会重复调用上游；更换录音后旧任务仍保存，但标记为旧版本。模型反馈中的时间必须位于录音时长内。

## 验证范围

构建后运行 `node scripts/verify_oral_analysis.mjs` 和 `node scripts/verify_oral_audio_ui.mjs`。接口测试使用隔离 Worker、D1、R2、合成 PCM 数据与模拟上游；界面状态测试覆盖录音替换、同意撤回、服务商变化和迟到响应，不产生真实调用费用。

真实音频服务商、手机麦克风及各浏览器的录音编解码仍需在单独配置音频 Provider 后进行验收。公开资源压缩和首次加载策略见 [加载优化](performance.md)。
